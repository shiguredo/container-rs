# バグ: macOS の exec で `containerWait` 失敗時に読み取りスレッド 2 本と FD 2 個がプロセス終了まで残る

- Created: 2026-08-04
- Completed: 2026-08-05
- Branch: feature/fix-macos-exec-fd-leak
- Polished: 2026-08-04

## 目的

macOS の `ContainerAsync::exec` で `containerWait` がエラーを返した場合に、stdout / stderr の読み取りスレッドと pipe FD が exec プロセスの終了まで回収されず蓄積する問題を修正する。

## 現状

- `src/core/client/xpc_client.rs` の `exec` は、stdout / stderr 用に pipe を作成し、`containerStartProcess` 後に読み取りスレッド 2 本 (`read_file_to_vec`) を起動してから `containerWait` を送信する
- `containerWait` がエラーを返すと、コメント (「wait 失敗時に join するとデーモン側が書き込み端を閉じるまで戻れない可能性があるため、読み取りスレッドはデタッチする」) の意図どおり読み取りスレッドをデタッチしたまま即 `Err` を返す (JoinHandle が drop され暗黙にデタッチされる)
- デタッチされたスレッドは、exec プロセスが生きている間はデーモン側が書き込み端を閉じないため、`read_file_to_vec` にブロックしたまま**読み取り端 FD 2 個を握り続ける** (自プロセスの書き込み端は close 済みだがデーモン側の dup が開いたまま)
- `containerWait` がエラーを返すのは、デーモンのエラー応答 (XPC エラー・エラー JSON) と `XpcTimeout` (`LONG_TIMEOUT` = 24 時間。実質発生しない) のケース。エラー応答の時点で exec プロセスが継続実行されている場合は、スレッドと FD はプロセス終了まで回収されず、失敗ごとに蓄積する (プロセス終了時には回収されるため永続リークではない)。エラー応答時にプロセスが既に終了していればデーモンが書き込み端を閉じて EOF になり、スレッドは自然に終了するためリークしない

## 設計方針

- エラーパスで読み取りスレッドが有限時間内に終了するよう、**エラーパス専用のキャンセルフラグ**を導入し、読み取りスレッドは `libc::poll` ベースの読み取りで FD の読み取り可能性を監視しつつ、poll のタイムアウトごとにフラグを確認して終了する方式に確定する (フラグが立ってから上限時間以内に読み取りを打ち切って終了する。poll のタイムアウトはフラグ確認間隔として上限時間以下に設定する)
- エラーパスで読み取り端 FD が閉じられると、デーモン側の書き込み端への書き込みが EPIPE になり、継続実行中のプロセスが出力喪失・終了し得る (デーモン実装依存)。exec は失敗済みであるため、この影響は許容する
- 「読み取り側を close して EOF を発生させる」案は不採用 (EOF は**書き込み端が全て閉じたとき**に発生するため、読み取り端の close では発生しない。また読み取り FD はスレッドに move 済みでエラーパスから close できず、二重 close のリスクがある)
- 「スレッドを強制終了する」案は不採用 (Rust の `std::thread` に強制終了 API は存在しない)
- デタッチの意図 (join によるハング回避) は維持する (エラーパスでは join しない)
- 正常系の読み取り契約 (EOF までブロックして読み切る) は変えない (キャンセルフラグはエラーパスでのみ立てる)

## 完了条件

- エラーパスでキャンセルフラグが立てられた後、読み取りスレッドが上限時間 (例: 5 秒) 以内に終了し、FD が回収されること (クレート内単体テスト。`containerWait` のエラーは統合テストで決定論的に再現できないため統合テストは対象外)
- 正常系の exec の挙動が変わらないこと (既存の exec 統合テストが引き続き通ること)

## 解決方法

- `src/core/client/xpc_client.rs` の `exec` に、エラーパス専用のキャンセルフラグ (`Arc<AtomicBool>`) を導入した。`containerWait` 失敗時にフラグを立ててから `Err` を返す
- 読み取りスレッドを `read_file_to_vec_cancellable` (新設) に変更し、`libc::poll` で FD の読み取り可能性を監視しつつ、poll のタイムアウト (100ms) ごとにフラグを確認する。フラグが立っているのを観測したら即座に読み取りを打ち切って `Ok(None)` を返し、FD を閉じて終了する (最悪でも poll 間隔 + read 1 回以内)
- 正常系 (フラグが立たない) では EOF まで読み切って `Ok(Some(bytes))` を返し、従来の読み取り契約を維持する。時間による打ち切りは行わない (5 秒超の exec でも出力を失わない)
- POLLERR / POLLNVAL は明示エラーにした。既存の `read_file_to_vec` は本番から未使用になったため削除し、64 MiB 上限・境界のテストを `read_file_to_vec_cancellable` に移行した
- デタッチの意図 (join によるハング回避) は維持する (エラーパスでは join しない)
- テスト: `read_file_to_vec_cancellable` の単体テスト 6 件 (キャンセルで終了・正常系 EOF・5 秒超の非打ち切り・小ファイル・64 MiB 上限超過・ちょうど 64 MiB 境界) を追加し、既存の exec 統合テスト (macOS) で正常系の挙動不変を確認した
